# Gameplay v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the fixed-lane prototype into a system-bar-safe gameplay loop with varied obstacles, score, capped difficulty, and complete local run controls.

**Architecture:** Extend the pure-Java engine with an injectable obstacle field and centralized difficulty policy, then expose immutable snapshots to the existing Canvas view. Keep Android layout, overlays, buttons, lifecycle, and accessibility in UI adapters so gameplay rules remain deterministic JVM-testable.

**Tech Stack:** Java 17, Android Views/XML, Canvas, Choreographer, AndroidX AppCompat/Core, JUnit 4, Robolectric 4.17, Gradle 8.11.1.

**Spec:** `docs/superpowers/specs/2026-10-30-gameplay-v2-design.md`

## Global Constraints

- Android Java with XML Views and the existing Canvas/Choreographer architecture; do not add a game framework.
- Portrait, min SDK 24, compile/target SDK 35.
- Normalized world coordinates describe only the playfield below the HUD.
- Frame simulation delta is capped at `0.05f`; score uses the same capped simulation time.
- Production random state continues across runs; tests inject deterministic `RandomSource` values.
- Difficulty constants: 15-second tiers, speed `min(0.30 + tier * 0.05, 0.65)`, interval `max(1.40 - tier * 0.12, 0.65)`, active cap 1/2/3 by tiers 0–1/2–3/4+.
- Login, SQLite, persistent high score, leaderboard, final art, sound, and online services remain out of scope.
- Every behavior change follows RED → GREEN and every task ends in a focused commit.

## Review Focus

- Non-finite, zero, negative, or oversized delta must not move entities, spawn bursts, or award abnormal score; Task 3 adds boundary tests.
- Repeated or extreme random lane values must remain in bounds and avoid an immediate repeated lane; Task 2 adds fake-sequence tests.
- Rapid repeated Pause/Resume/Restart/Play Again taps must not create duplicate frame callbacks or corrupt state; Task 6 adds repeated-click tests.
- Background/foreground transitions from PLAYING, PAUSED, READY, and GAME_OVER must preserve the correct state and never resume unexpectedly; Task 6 adds lifecycle tests.
- API 24 and API 35 system-bar insets must not accumulate after repeated dispatch; Task 1 tests idempotent inset application on both SDK levels.
